# Аудит безопасности гостевого WiFi кафе

> **Статус:** черновик. Раздел «Результаты» заполняется по данным, собранным на
> устройстве в самом кафе. Рекомендации (раздел 4) применимы уже сейчас.
> **Дата:** 2026-05-26

---

## 1. Контекст, авторизация и границы

Владелец кафе попросил оценить, насколько его гостевой WiFi устойчив к зловредным
действиям случайных посетителей. Проверка проводится **с разрешения владельца** и
носит **защитный (defensive)** характер: цель — найти слабые места конфигурации и
закрыть их, а не атаковать сеть.

**Что осознанно НЕ выполняется (это и есть «вредные действия»):**

| Техника | Почему исключена |
|---|---|
| Deauth / disassociation, глушение эфира | Отключает всех посетителей разом — прямой вред |
| Перехват/анализ чужого трафика (sniffing) | Затрагивает приватность третьих лиц |
| Evil-twin / поддельная точка доступа | Обман посетителей, перехват их данных |
| Перебор WPS PIN | Может «подвесить»/заблокировать роутер |
| Brute-force пароля роутера/WPA, взлом handshake | Атака, выходящая за рамки оценки конфигурации |

Тестирование ограничено **пассивной диагностикой конфигурации** точки доступа, к
которой у владельца есть права.

**Ограничение среды выполнения:** аудит готовился ассистентом в изолированном
облачном контейнере (нет WiFi-адаптера, исходящий доступ по allowlist). Контейнер
не находится в сети кафе, поэтому «живые» замеры выполняются вручную на устройстве,
физически подключённом к гостевому WiFi (см. Приложение A).

## 2. Методология (безопасная самодиагностика)

На устройстве, подключённом к гостевой сети кафе, собираются следующие данные:

1. Тип шифрования и шифр сети (Open / WPA2 / WPA3, TKIP/CCMP).
2. Идентификация шлюза/роутера (IP, по возможности модель).
3. Доступность веб-админки роутера из гостевой сети (только факт ответа, без входа).
4. DNS-резолверы, выдаваемые по DHCP (нет ли подмены).
5. Изоляция клиентов (AP/client isolation) — пассивно, по ARP-таблице.
6. Открытые сервисы на самом роутере (опционально, лёгкий скан только адреса шлюза).
7. Наличие и защищённость captive portal.

## 4. Рекомендации по защите (hardening)

Базовый набор мер для небольшого кафе — от самых важных к дополнительным:

1. **Отдельная гостевая сеть + изоляция клиентов.** Гостевой WiFi должен быть в
   отдельной сети/VLAN, без доступа к кассе, камерам, рабочим ПК и админке роутера.
   Обязательно включить **AP/Client Isolation** («изоляция клиентов») — тогда
   посетители не видят устройства друг друга.
2. **Шифрование WPA3 (или минимум WPA2-AES/CCMP).** Полностью открытая сеть (Open)
   позволяет любому в зоне действия пассивно читать чужой незашифрованный трафик.
   Если нужен бесшовный вход — использовать WPA3-SAE с общим паролем на табличке,
   либо OWE (Enhanced Open).
3. **Отключить WPS.** Это частый вектор подбора и компрометации.
4. **Сменить дефолтные учётные данные роутера** (admin/admin и т.п.) на сложный
   пароль; отключить удалённое управление из интернета.
5. **Закрыть веб-админку от гостевой сети.** Доступ к настройкам — только из
   рабочего сегмента или по кабелю.
6. **Актуальная прошивка роутера** и регулярные обновления (закрытие известных CVE).
7. **Доверенный DNS** (провайдер/публичный резолвер); по возможность DNS-фильтрация
   вредоносных доменов.
8. **Гостевой captive portal только по HTTPS**; не собирать лишние персональные данные.
9. **Лимиты на гостя:** ограничение полосы и числа подключений снижает влияние одного
   «шумного» клиента.
10. **Регулярный мониторинг** подключённых устройств и логов роутера.

## 5. Приложение A. Безопасные команды для macOS

Запустить в **Terminal**, находясь в кафе и подключившись к их WiFi. Команды
**только читают** конфигурацию, ничего не меняют и не атакуют сеть. Sudo не нужен.
Если в выводе SSID окажется пустым/`<redacted>` — нужно разрешить Terminal доступ к
геолокации (System Settings → Privacy & Security → Location Services), это требование
свежих macOS для показа имени сети.

```bash
# ====== WiFi self-assessment (safe, read-only) ======
echo "## macOS version"; sw_vers

WIFI=$(networksetup -listallhardwareports | awk '/Wi-Fi|AirPort/{getline; print $2; exit}')
echo; echo "## Wi-Fi interface: $WIFI"

echo; echo "## Текущая сеть и тип шифрования"
system_profiler SPAirPortDataType 2>/dev/null | sed -n '/Current Network Information/,/Other Local Wi-Fi/p'

echo; echo "## SSID"
networksetup -getairportnetwork "$WIFI"

echo; echo "## IP / MAC интерфейса"
ipconfig getifaddr "$WIFI"
ifconfig "$WIFI" | grep -E 'inet |ether'

echo; echo "## Шлюз (роутер)"
route -n get default 2>/dev/null | grep -E 'gateway|interface'
GW=$(route -n get default 2>/dev/null | awk '/gateway/{print $2}')
echo "Gateway = $GW"

echo; echo "## DNS-серверы"
networksetup -getdnsservers "$WIFI"
scutil --dns | awk '/nameserver/{print}' | sort -u

echo; echo "## Соседи в сети (пассивно, ARP-таблица — индикатор изоляции клиентов)"
arp -a

echo; echo "## Доступность админки роутера (только заголовки, без входа)"
[ -n "$GW" ] && curl -s -I --max-time 5 "http://$GW" 2>/dev/null
[ -n "$GW" ] && curl -s -I -k --max-time 5 "https://$GW" 2>/dev/null

echo; echo "## (Опционально) скан только самого роутера, если установлен nmap:"
echo "   nmap -sV $GW"
echo "## ====== конец ======"
```

> Примечание: WPS и часть настроек роутера с macOS напрямую не видны — их проще
> проверить на странице администрирования роутера (раздел Wireless/Security).
